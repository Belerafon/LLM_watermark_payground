# LLM Watermarking Playground

Локальная переработка [nohypeai/watermarking-playground](https://huggingface.co/spaces/nohypeai/watermarking-playground).

Инференс идёт в браузере: Transformers.js и ONNX Runtime. Водяной знак ставится на логиты во время генерации. В списке есть Gemma 4 E2B/E4B, Qwen3-0.6B/1.7B и SmolLM3-3B. Используются турнирное семплирование в духе SynthID-Text и зелёный/красный список Kirchenbauer.

Оригинал — статический Space на Hugging Face. Модели там не лежали в репозитории страницы: браузер качал их с Hugging Face Hub. Здесь веса тоже скачиваются с `huggingface.co`, только после нажатия «Загрузить модель».

## Запуск

Дважды щёлкните `start.bat`. Откроется http://127.0.0.1:8765/

Закрытие окна останавливает сервер. Не открывайте `index.html` двойным щелчком: воркеры и WebGPU с `file://` не работают. Заголовки изоляции выставляет `serve.py`.

## Онлайн

GitHub Pages: Settings → Pages → Branch `main` → `/ (root)`. Адрес будет `https://belerafon.github.io/LLM_watermark_payground/`.

Посетитель ничего не качает руками. Браузер сам берёт `onnx-community/gemma-4-E4B-it-ONNX` с Hugging Face. Это около 5 ГБ в кэш браузера, один раз. Нужны Chrome или Edge с WebGPU.

GitHub Pages не ставит заголовки изоляции для WebGPU. Их добавляет `coi-serviceworker.js` (страница один раз перезагрузится).

Локально по-прежнему `start.bat`. Если веса уже лежат в `models/`, страница возьмёт их и в сеть не пойдёт. Докачка: `download_gemma4.ps1`.

В каталоге моделей также доступна Qwen3-1.7B в ONNX Q4F16 (примерно 1,4 ГБ). На GitHub Pages веса скачиваются из Hugging Face при первом нажатии «Загрузить модель». Для локального запуска весов используйте `download_qwen3_1_7b.ps1`. Эта модель помечена как WebGPU-only: откат на Q8 в WASM отключён, поскольку браузерный WASM-модуль имеет отдельный предел памяти, не связанный с объёмом системной RAM.

Добавлены ONNX Q4F16 варианты Gemma 4 E2B и SmolLM3-3B. Кнопка «Скачать в кэш» сохраняет веса и токенизатор без создания ONNX-сессии; «Загрузить из кэша» запускает модель без сетевой загрузки весов. Кэшированные веса показываются в списке и удаляются оттуда. Для этих моделей нужен WebGPU. SmolLM3 использует preview-сборку Transformers.js v4 с CDN.

## Что в репозитории

- `index.html`, `main.js`, `worker-v4.js`, `watermark.js`, `models.js`, `style.css` — страница
- `vendor4/` — Transformers.js 4.3.0 и WASM ONNX Runtime, чтобы страница не ходила в CDN
- `serve.py`, `start.bat`, `start.ps1` — локальный сервер
- `download_gemma4.ps1` — докачка весов

## Как читать результат проверки

Шкала «сила» показывает величину сигнала, а не вероятность авторства ИИ. В турнире она сравнивает долю служебных оценок 1 с уровнем 50% и расчётным ориентиром для выбранного числа раундов. Ориентир получен на искусственном распределении вариантов, не на загруженной модели; это не максимальное возможное значение. В зелёном списке шкала показывает превышение над заданной долей γ. При достаточном объёме данных от 30% показывается слабый сигнал, от 70% — сильный.

Статистики z и p показаны отдельно. Они приближённые; универсальный порог z = 4 не делает этот демонстрационный детектор откалиброванным для любых текстов и настроек. Для оценки частоты ложных срабатываний нужен корпус текстов без метки. Одинаковый токен после того же контекста учитывается в статистике и шкале один раз, но раскраска сохраняется для всех позиций. Такой подход к повторам используется и в [исходном детекторе зелёного списка](https://github.com/jwkirchenbauer/lm-watermarking/blob/main/watermark_processor.py).

Проверка расчётов и отображения результата без загрузки модели: `node --test tests/watermark.test.mjs`. Тесты используют искусственные последовательности токенов и не заменяют проверку качества на реальных текстах.
